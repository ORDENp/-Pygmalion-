## 2. Правила триад (T1-T5)

### Структура триад:
```javascript
T1: Знания      → У.Е. №1, 2, 3    (3 шт.)
T2: Практики    → У.Е. №4, 5, 6    (3 шт.)
T3: Творчество  → У.Е. №7, 8, 9    (3 шт.)
T4: Досуг/ЗОЖ   → У.Е. №10, 11, 12 (3 шт.)
T5: №21         → У.Е. №21         (1 шт.)
```

### Правила эмиссии:
1. **Минимум**: 3 У.Е. (одна триада T1-T4)
2. **Максимум**: 13 У.Е. (все 4 триады + №21)
3. **Лимит на период**: 26 У.Е. максимум
4. **У.Е. №21**: доступна ТОЛЬКО после активации хотя бы одной триады (T1-T4)

### ❌ НЕПРАВИЛЬНО (из текущего backend):
```javascript
// Произвольные значения "от фонаря"
{"amount_generated": 100}  // ← НЕТ! Нет такого понятия!
{"amount": 30}             // ← НЕТ! Нельзя передать 30 У.Е.!
```

### ✅ ПРАВИЛЬНО:
```javascript
// Эмиссия триады T1 (3 У.Е.)
{
  "act_type": "EMISSION",
  "actor_ok": "::test.1::",
  "payload": {
    "triads": ["T1"],           // Выбранные триады
    "ue_ids": [1, 2, 3],        // Конкретные номера У.Е.
    "total_amount": 3,          // Всегда = сумма У.Е. из триад
    "phase": "active"           // или "impulse" (если 20:00-03:59)
  }
}

// Передача У.Е. №1
{
  "act_type": "TRANSFER",
  "actor_ok": "::test.1::",
  "target_ok": "::test.2::",
  "payload": {
    "ue_id": 1,                 // Конкретная У.Е.
    "triad": "T1",              // Триада
    "amount": 1,                // Всегда 1 (У.Е. неделимы)
    "reason": "за помощь"       // Опционально
  }
}
```

## 3. Канон "24+4" (Иммунитет Импульса)

### Фазы системы:
- **04:00–19:55** → `active` (активная фаза, 24 часа)
- **19:55–20:00** → `silence` (зона тишины, эмиссия запрещена)
- **20:00–03:59** → `impulse` (импульсная фаза, 28 часов)

### Правила сгорания:
```
burnAt = следующая полночь после даты эмиссии (+1 день)
```

**Примеры:**
- Эмиссия 15:00 → burnAt = завтра 00:00 (через 9 часов)
- Эмиссия 22:00 → burnAt = завтра 00:00 (через 26 часов)
- Эмиссия 02:00 → burnAt = сегодня 00:00 (через 22 часа)

### Статусы У.Е.:
- `impulse` → эмитирована в 20:00-03:59, активируется в 04:00
- `active` → эмитирована в 04:00-19:55, активна сразу
- `transferred` → передана другому О.К.
- `burned` → сгорела в полночь

### ❌ У.Е. НЕ "сгорают" физически!
Они **выходят за границу окна восприятия**. `acts_log` остаётся неизменным.

## 4. Карма и признание

### Правила начисления:
1. **+2 кармы** → О.К., который передал У.Е. до полуночи
2. **+1 У.М.** → О.К., который получил благодарность (У.М.)
3. **0 кармы** → О.К., который не передал У.Е. (сгорела)

### У.М. (Условные Метки):
- Начальный баланс: **5 У.М.**
- Вес каждой У.М.: **1** (все равны)
- У.М. можно передавать как благодарность за акты

## 5. Архитектура хранения

### Исходная структура (localStorage):
```javascript
crystal_state  → оперативная модель (текущее состояние)
ro_dag         → граф связей (append-only)
acts_log       → полный журнал всех актов
```

### Целевая структура (PostgreSQL):
```sql
ok_identity       → О.К. (Открытые Ключики)
acts_log          → append-only журнал актов
ro_dag_edges      → граф связей
acts_annotations  → слой интерпретаций (У.М.)
```

## 6. Типы актов

### Основные:
- `EMISSION` → эмиссия У.Е.
- `TRANSFER` → передача У.Е.
- `BURNED` → сгорание У.Е.

### Дополнительные:
- `TEMPORARY_CREATED` → создание Вр.У.З. (временная условная задача)
- `TEMPORARY_CONFIRMED` → подтверждение Вр.У.З.
- `TEMPORARY_CANCELLED` → отмена Вр.У.З.
- `PHASE_CHANGE` → смена фазы системы
- `TRIAD_RESET` → сброс триад (новый период)

### Социальные:
- `ORDER_JOIN` → вступление в Орден
- `DEPARTMENT_JOIN` → вступление в Отдел
- `UNION_CREATED` → создание Союза
- `COUNCIL_CREATED` → создание Совета

## 7. Что НЕ нужно реализовывать

### ❌ Burn-scheduler
**Причина:** Создаёт "второй источник истины", нарушает Event Sourcing.

**Решение:** TimeRhythm как единственный источник времени. У.Е. не "сгорают" физически — они выходят за границу `window_start`.

### ❌ Материализованные балансы
**Причина:** Нарушает принцип проекции.

**Решение:** Всегда считать через `acts_log` с фильтром по `window_start`.

### ❌ Произвольные суммы У.Е.
**Причина:** Нарушает правила триад.

**Решение:** Валидация на уровне API — только триады T1-T5.
